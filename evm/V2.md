# GachaMachine v2

Implemented in `evm/src`. Live Base bytecode is still v1 until we redeploy.

## Done in source

- Donate mints one same-tier capsule. Donor picks the bag: `donateNFT(..., rarityId)`. Donate into a bag reverts while that bag has `pendingDraws > 0`. Buy still mints capsules.
- Same collection can be approved for multiple rarities (`approvedForRarity`). Token standard is frozen on first approve.
- Donate checks `ownerOf` / `balanceOf` after transfer. Callbacks only accept the expected `(token, from, id, amount)`.
- `rescueStuckDraw(requestId)` — player after `rescueDelay` (default 1 day), admin anytime.
- Claim-queue tokens are reserved; bag withdrawals cannot take a slot counted by `pendingDraws`.
- `nonReentrant` on purchase, withdraw, donate, redeem, play, claim, rescue, `withdrawPrize`.
- Two-step admin: `transferAdmin` / `acceptAdmin` moves both `ADMIN_ROLE` and `DEFAULT_ADMIN_ROLE`.
- `ECONOMIST_ROLE` can pause/unpause, `setRarityPrice`, and `setRarityEnabled`. `ADMIN_ROLE` is its role admin and can still pull those levers. Withdraw, prize pulls, `approveNFT`, `registerRarity`, VRF, and rescue stay admin-only.
- `Pausable` on purchase / play / donate. Claim and rescue stay open.
- `PrizeClaim` packs `tokenContract` + `isERC721` + `assignedAt`. The timestamp is for off-chain monitoring; claim is not delayed on-chain.
- Purchase requires exact `msg.value`.
- Admin prize pulls are instant: `redeemPrize` (LIFO) and `withdrawPrize` (indexed, identity-checked). No fake timelock.
- VRF coordinator is immutable. `cancelVrfSubscription` still returns leftover native/LINK. `createVrfSubscription` opens a new sub on that same coordinator. `setVRFConfig` cannot change coordinator or run while draws are pending.
- `registerRarity` uses `_tokenToRarityPlusOne` (no loop).
- `getPrizeInfo` returns the full `PrizeInfo`.
- Draw snapshots `bagLength` at `play`. Fulfillment is `random % min(snapshot, current length)`, so a post-play donation cannot inflate the modulo after the VRF word is public.
- Direct ERC1155 / safe ERC721 transfers revert unless they go through `donateNFT`.
- Each `GachaNFT` only enables token id 0. Machine always mints/burns `CAPSULE_ID`.
- Deploy script grants the machine `MINTER_ROLE` and revokes it from the deployer.

## Product calls locked in

- Eligible set is frozen at play (`random % min(bagLength snapshot, current bag)`). Unopened capsules still see later donations; in-flight draws do not. Snapshot stops the cheap sandwich. Donate into a bag is also blocked while that bag has a pending draw, so a donation cannot occupy a slot vacated by another fulfill. Admin `withdrawPrize` can still reorder slots.
- ERC1155 `amount = N` is still one bag slot / one capsule.
- Admin is a hot wallet. A stolen key can drain bags. An economist bot can reprice and pause without withdraw access. Donation dilution is an approval-policy problem: do not approve open mints into a valuable bag.
