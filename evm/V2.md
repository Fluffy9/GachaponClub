# GachaMachine v2

Implemented in `evm/src`. Live Base bytecode is still v1 until we redeploy.

## Done in source

- Donate mints one same-tier capsule. Donor picks the bag: `donateNFT(..., rarityId)`.
- Same collection can be approved for multiple rarities (`approvedForRarity`).
- `rescueStuckDraw(requestId)` — player after `rescueDelay` (default 1 day), admin anytime.
- Claim-queue tokens are reserved; bag withdrawals cannot take a slot counted by `pendingDraws`.
- `nonReentrant` on purchase, withdraw, donate, redeem, play, claim, rescue, execute withdrawal.
- Two-step admin: `transferAdmin` / `acceptAdmin` moves both `ADMIN_ROLE` and `DEFAULT_ADMIN_ROLE`.
- `Pausable` on purchase / play / donate. Claim and rescue stay open.
- Purchase requires exact `msg.value`.
- Prize withdrawal id is `abi.encode` + nonce; bag slot is removed at schedule time.
- `registerRarity` uses `_tokenToRarityPlusOne` (no loop).
- `getPrizeInfo` returns the full `PrizeInfo`.
- Direct ERC1155 / safe ERC721 transfers revert unless they go through `donateNFT`.
- Each `GachaNFT` only enables token id 0. Machine always mints/burns `CAPSULE_ID`.
- `cancelVrfSubscription(to)` — admin, no pending draws. Sends leftover native/LINK to `to` and zeros `subscriptionId`. Play reverts until `setVRFConfig` has a live sub. Does **not** recover the live v1 0.005 ETH.

## Product calls locked in

- Odds are at fulfillment (`random % bag.length` when VRF returns). FAQ already says this.
- ERC1155 `amount = N` is still one bag slot / one capsule.
- `redeemPrize` stays an instant admin LIFO pop. Timed path is `schedulePrizeWithdrawal`.

## After redeploy

Update `gacha/src/lib/constants.ts` machine + NFT addresses and `EVM_DEPLOY_FROM_BLOCK`.
Fund a new VRF sub. Re-approve collections per bag.
Leftover float on a v2 machine-owned sub can be recovered with `cancelVrfSubscription`. The live v1 machine still cannot.
